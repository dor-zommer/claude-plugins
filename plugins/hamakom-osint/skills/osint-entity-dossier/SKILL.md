# osint-entity-dossier - תיק ישות חוצה-מאגר

סקיל לבניית תיק רקע על ישות (אדם / חברה / משרד) על פני כל טבלאות osint-db בבת אחת. התוצר אינו "פרופיל מאומת" אלא **תיק לידים לבדיקה** מקובץ לפי תחום, שכל פריט בו מקושר למקור הרשמי שלו וטעון אימות לפני שהוא נכנס לכתבה.

**קרא קודם `references/db-map.md`** - העמודות המאונדקסות, חוק הזהב של השאילתות, ומצב הסקרייפרים. תיק שנבנה בלי לדעת אילו טבלאות תקועות יציג "אין" במקום "לא נאסף".

## עקרונות יסוד

1. **התאמת שם אינה אישור זהות.** "ישראל ישראלי" ב-`exemptions` ו-"ישראל ישראלי" ב-`knesset_mk_individuals` אינם בהכרח אותו אדם. כל פגיעה היא ליד; הקישור בין שתי פגיעות הוא השערה לבדיקה - לא עובדה. אמת זהות מול מזהים (`supplier_ids`, `mk_individual_id`) והמקור הרשמי לפני שאתה מחבר.
2. **המאגר מחזיר רשומות גולמיות.** כל שורה היא רישום ראשוני. הופך לסיפור רק אחרי פתיחת ה-URL הרשמי (`detail_url` / `url` / `pl_url` / אתר הכנסת) ואימות.
3. **תיק אינו האשמה.** ריבוי הופעות אינו מעיד על עוולה. נסח את התיק כמפה של קשרים-לבדיקה, לא כתב אישום.
4. **הבחן ציבורי מפרטי.** חברה, משרד, ח"כ, בכיר ציבורי - לגיטימי לתחקר. אדם פרטי שצף בהתאמה אקראית - אל תבנה עליו תיק; ציין שזו התאמת שם בלבד.
5. **כשאי-אפשר לקבוע - הערך כיוון והסתברות.** לכל קשר בין-תחומי תן רמת ביטחון (גבוהה/בינונית/נמוכה) שזו אותה ישות, ומה יכריע.
6. **ישויות חבויות תחת שם-גג.** גופים רבים אינם מופיעים בשמם המוכר אלא תחת **ארגון-האם** או שם רשום. חיפוש השם הצר לבדו יחזיר כמעט כלום, בעוד חיפוש שם-הגג יפתח את הכול - אבל אז ייכללו גם זרועות אחרות של אותו ארגון. חובה אז להפריד בתוך התוצאות לפי תחום/ניסוח את מה ששייך לישות המבוקשת מהשאר, ולתת ביטחון לכל ייחוס. דוגמה אמיתית: "החטיבה להתיישבות" כמעט ריקה במאגר; "ההסתדרות הציונית העולמית" (ארגון-האם) מחזיר מאות מיליונים - אך חלקם זרועות חינוך/תרבות שאינן החטיבה.

## שלב 1 - חיפוש רוחבי בקריאה אחת

הנתיב הראשי:
```
search_entity("שם הישות")
```
מחזיר התאמות מ-exemptions (ספקים/אנשי קשר), knesset_mk_individuals, legislation, mevaker_reports, mavat_plans, yosh_plans ו-decisions - כל שורה מתויגת בטבלת המקור שלה. השתמש בשם מדויק ככל האפשר כדי לצמצם רעש; אם רחב מדי הוא ייקטע.

הרחב per_table_limit אם צריך יותר תוצאות לטבלה: `search_entity("שם", 50)`.

> **`search_entity` אינו סורק את טבלאות הכסף - זה החור הגדול בתיק.** הכלי מכסה 7 טבלאות בלבד והוא **עיוור ל-`budget_contracts` (מיליון שורות), `budget_supports` (330 אלף), `amutot` (75 אלף) ו-`mod_tenders`**, בלי להודיע על כך. תיק שנבנה עליו לבד מפספס את מפתח התקציב וגיידסטאר לגמרי. **חובה להשלים אותן ידנית - ראה `osint-money`**, ובמיוחד את המלכודת ש-`LIKE` על `budget_contracts.supplier_name` נקטע ושהכניסה היחידה לטבלה היא `publisher_name=` או `entity_id=`.

> **שתי תקלות פעילות בכלי:** (א) על `exemptions` הוא נקטע בשקט כשהמונח לא מצמצם, ומחזיר שורה קטנה `{"table":"exemptions","note":"scan too broad (aborted)"}` - אם היא בפלט, **אין מסקנה** על פטורים, וזה לא "אין התאמות"; חזור עם `query_db`. (ב) על `mevaker_reports` הוא מחזיר שדות זבל `"ministry"` ו-`"type"` (העמודות אינן קיימות בטבלה) - ההתאמה תקינה, התעלם מהשדות.

**אם החיפוש הצר חוזר כמעט ריק - חפש את שם-הגג.** לפני שמסיקים "אין במאגר", בדוק את ארגון-האם / השם הרשום / השם ההיסטורי. הרחבות שכדאי לנסות:
- גוף ציבורי/סטטוטורי → הרשות/החברה/ההסתדרות שמעליו (למשל החטיבה להתיישבות → "ההסתדרות הציונית העולמית").
- חברה → שם רשום מלא וגם שם מותג קצר, עם/בלי "בע"מ", וגם חברות-בת.
- אדם → שם מלא, שם פרטי+משפחה, וכינוי ציבורי.
- ראשי תיבות מול שם מלא (קק"ל / קרן קימת לישראל).

כשנפתח דרך שם-גג - סמן כל רשומה אם היא **באמת** הישות המבוקשת (לפי תחום/ניסוח/מזהה) או זרוע אחרת של הגג, ותעד את ההבחנה בתיק.

## שלב 2 - העמקה לכל פגיעה (query_db מול העמודות האמיתיות)

**התקשרויות בפטור:**
```sql
SELECT id, title, publisher, supplier_names, supplier_ids, amount_ils,
       exemption_type, contract_purpose, update_date, detail_url
FROM exemptions
WHERE supplier_names LIKE '%שם%' OR contact_name LIKE '%שם%'
ORDER BY amount_ils DESC
```

**תכנון ובנייה (כל ישראל):**
```sql
SELECT pl_number, pl_name, district_name, plan_county_name, pl_area_dunam,
       depositing_date, pl_url
FROM mavat_plans
WHERE pl_name LIKE '%שם%' OR ja_concat LIKE '%שם%'
ORDER BY depositing_date DESC
```
(לתכנון ביו"ש - אותו דבר על `yosh_plans`.)

**כנסת - זיהוי ה-ח"כ ואז יוזמות:**
```sql
SELECT mk_individual_id, mk_individual_name, mk_individual_name_eng
FROM knesset_mk_individuals
WHERE mk_individual_name LIKE '%שם%';

SELECT b.name, b.type_desc, b.status_id, b.publication_date
FROM knesset_bill_initiators i
JOIN knesset_bills b ON b.id = i.bill_id
WHERE i.mk_individual_id = <ID>;
```
(לפרופיל כנסת מלא - הפנה ל-osint-knesset.)

**מבקר המדינה** (העמודות הן `id, title, url, pub_date, content_html, content_text, summary` - **אין `ministry` ואין `type`**):
```sql
SELECT id, title, pub_date, url
FROM mevaker_reports
WHERE title LIKE '%שם%' OR content_text LIKE '%שם%'
ORDER BY pub_date DESC
```
חיפוש בגוף הדוח (`content_text`) עובד - הטבלה קטנה (145 דוחות) והוא הכלי החזק כאן, כי שם הישות מופיע בתוך הדוח ולא בכותרת. לעומק - ראה `osint-comptroller`.

**כסף: התקשרויות בפועל ותמיכות** (מה ש-`search_entity` פספס). ב-`budget_supports` האינדקס הוא על ה-`recipient_entity_id` ולא על השם, ולכן `LIKE` על השם **חייב** צמצום קודם ב-`year` או ב-`supporting_ministry` - בלעדיו הוא נקטע:
```sql
SELECT recipient_entity_name, supporting_ministry, year, amount_approved, amount_paid, purpose
FROM budget_supports
WHERE year = 2024                          -- חובה: צמצום לפני ה-LIKE
  AND recipient_entity_name LIKE '%שם%'
ORDER BY amount_paid DESC
```
עבור על השנים אחת-אחת (2020-2025 בטבלה) וחבר. אם מצאת התאמה, קח את ה-`recipient_entity_id` שלה והמשך דרכו - הוא מאונדקס ולא צריך צמצום:
```sql
SELECT year, supporting_ministry, amount_approved, amount_paid, purpose
FROM budget_supports WHERE recipient_entity_id = '<id>' ORDER BY year DESC
```
```sql
SELECT name_he, status, classification, revenue, expenses, employees, nihul_takin, last_report_year
FROM amutot
WHERE name_he LIKE '%שם%'
```
ל-`budget_contracts` **אין** נתיב חיפוש לפי ספק - ראה `osint-money`.

**חקיקה ותזכירים + החלטות ממשלה:**
```sql
SELECT id, title, ministry, type, pub_date, url FROM legislation WHERE title LIKE '%שם%' OR ministry LIKE '%שם%';
SELECT id, title, decision_date, source, summary, url FROM decisions WHERE title LIKE '%שם%' OR summary LIKE '%שם%';
```

## שלב 3 - הצלבה וזיהוי קשרים בין-תחומיים

הנקודה התחקירנית: אותו שם שמופיע כ**ספק בפטור** + **יזם תוכנית** + **נושא בדוח מבקר** + **ח"כ**. לכל חיבור כזה:
- בדוק שזו אותה ישות (מזהה חברה זהה? שם מלא תואם? הקשר גיאוגרפי/תחומי מתיישב?).
- תן רמת ביטחון לזהות (גבוהה/בינונית/נמוכה).
- ציין מה יאשש או יפריך (ח"פ, ת"ז ציבורית של נבחר, מסמך רשמי).

חיבור בין שתי טבלאות הוא הליד החזק ביותר בתיק - וגם זה שהכי קל לטעות בו על בסיס שם בלבד.

## שלב 4 - העשרה ואימות מול המקור הרשמי

לכל פריט בתיק שמדורג לפרסום, פתח את ה-URL הרשמי (`detail_url` לפטור, `pl_url` לתכנון, `url` למבקר/חקיקה/החלטות, אתר הכנסת לחקיקה) ואמת את הרשומה. רק פריט שעבר אימות מול מקורו נכנס לתיק כ"מאומת"; השאר נשארים "ליד לבדיקה".

## התמודדות עם תקלות

| תקלה | פתרון |
|---|---|
| search_entity מחזיר ריק | קצר/הרחב את השם, נסה שם חברה לעומת שם פרטי, או חפש ידנית עם LIKE בכל טבלה |
| search_entity נקטע ("too broad") | השם רחב מדי - הוסף מילה מזהה (שם פרטי+משפחה, שם חברה מלא) |
| יותר מדי התאמות (שם נפוץ) | סנן לפי הקשר (משרד, מחוז, תקופה); ציין במפורש שזה שם נפוץ והתאמה אינה זהות |
| התאמה ב-exemptions אבל supplier_ids ריק | אמת זהות מול detail_url; בלי ח"פ - סמן "זהות לא אומתה" |
| שתי פגיעות שנראות אותה ישות אך לא בטוח | אל תחבר; תעד כשתי רשומות נפרדות עם הערת ביטחון |

**אסור:** לחבר רשומות מטבלאות שונות לישות אחת על סמך שם בלבד, ולהציג את החיבור כעובדה. כל חיבור - השערה עם רמת ביטחון עד לאימות.

## אתיקה

הפרד בין דמות/חברה ציבורית (שניתן לתחקר) לאדם פרטי (שאינו נושא לתיק). שם נפוץ מחייב זהירות כפולה - ציין במפורש כשהתאמה היא שם בלבד. אל תייחס מניע, אל תקבע קשר אישי, ואל תפרסם פרטים מזהים של אדם פרטי שצף בהתאמה אקראית.

## ניהול העבודה

פתח רשימת משימות (TaskCreate): חיפוש רוחבי (search_entity), העמקה לכל תחום, הצלבה וזיהוי קשרים, אימות זהות מול מזהים ו-URL רשמי. עדכן רמת ביטחון לכל קשר תוך כדי.

## דוח הדסק - מבנה קבוע

```markdown
# תיק: [שם הישות]

## סוג הישות והיקף החיפוש
[אדם / חברה / משרד; מה נסרק; אם שם נפוץ - אזהרה מפורשת]

## הופעות לפי תחום
### התקשרויות (פטורים)
[רשומות + סכומים + detail_url]

[תוכניות + מחוז + pl_url]
### כנסת
[ח"כ/יוזמות + קישור]
### מבקר המדינה
[דוחות + url]
### חקיקה והחלטות ממשלה
[פריטים + url]

## קשרים בין-תחומיים (הלידים החזקים)
[כל חיבור: אילו שתי טבלאות, רמת ביטחון שזו אותה ישות, מה יכריע]

[רשימת בדיקות: ח"פ/זהות, פתיחת URL-ים, הצלבות נוספות]

ומה חוסם אותו מלהיות סיפור]

```

כתוב בעברית, בלי אימוג'ים, חד וקצר. התיק צריך לתת לעורך תמונת קשרים תוך דקה - עם הבחנה ברורה בין מה שאומת לבין מה שהוא עדיין התאמת שם.
